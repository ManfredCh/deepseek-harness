# Agent Note: 让 skill 描述保持在模型可见目录预算内

Status: implemented

[English](2026-09-14-skill-description-catalog-budget.md) | 中文

## 问题

`dsh-tool-skill` 以 `catalogDescriptionMaxLength`（默认 500）渲染会话 skill 目录，超出者被硬截断并补省略号。截断发生在渲染期，源文件完好，因此 code review 看不到；而被截掉的正是描述尾部——按惯例，那里恰好写着该 skill 何时适用。

仓库里有两个 skill 超限。`record-browser-gif`（569 字符）丢掉了那半句话，而它承载着硬性要求：每个改动产品用户可见 GUI 的 PR 都必须附一段录自真实服务与模型链路的 GIF。`dsh-doc`（518）丢掉了 `Use for` 列表的结尾。两者都仍是合法 Markdown，通过了全部门禁，并以选择信号被切断的状态送到模型面前。

目录也没有总量约束。`catalogDescriptionMaxLength` 限制单条描述，没有任何东西限制它们之和，而渲染出的目录是每个请求都要付的成本。

## 决策

`scripts/verify-skill-descriptions.ts` 对仓库 skill 描述施加门禁，注册为 `verify-skill-descriptions`，并作为 `doc-sync` 与 `doc-quick` 的 `skill-descriptions` 叶子。它强制四条规则：

- 每个 `.agents/skills/*/SKILL.md` 的描述不超过 **450 字符**——即 500 的渲染上限减去 50 字符余量，使日常改写无法悄悄越线。
- 每条描述要么说明何时使用（`Use when`、`Use before`、`Use for` 或 `Use to`），要么改而声明其边界（`Do not use`）。
- 提到另一个仓库 skill 的描述同时要带边界措辞，使交叉引用起到消歧作用而不是重复声明同一件事。
- 所有描述合计不超过 **4500 字符**的目录预算，且任意两条描述共享的实词不超过一半。

仓库全部十二条描述都已改写以符合规则，去掉了本属于 skill 正文而非选择信号的实现细节（工具名、参数名、编码步骤）。最长的一条现为 412 字符，合计 3925。

`AGENTS.md` 另有一处重复指针：一个独立句子重述了持久化类型确认义务，而它前一段已经链接了同一份文档。该义务已并入前一段的链接文本，独立句被删除，词数持平。

### 减法审计结论

同一次检查还针对仓库中面向模型的散文，排查了在模型能力更强之后已无必要的三类过时指导：鼓励跑测试与自检、要求行动前必须读文件的笼统义务、以及为约束早期模型而写的强硬"先问"措辞。对 `AGENTS.md`、`docs/`、`packages/AGENTS.md` 与 `.agents/skills/` 的模式扫描显示，第一类和第三类完全不存在。第二类只以"按用途路由"的形态出现——`AGENTS.md` 把架构阅读限定在改动 `packages/` 时，`docs/architecture.md` 复述了同一范围，而不是要求预先通读一切。`AGENTS.md` 里那两行测试规则是**约束**测试而非鼓励测试，且没有其它文件陈述它们，因此都不过时。上述重复指针是本次审计唯一有依据的删除。

## 考虑过的替代方案

**保持渲染期截断，靠 review 把关。** 否决：该失效在构造上就不可见。源文件完好、现有门禁全部通过，因此只有度量渲染长度的门禁才能发现它。那两条超限描述一直以这种状态发布。

**提高 `catalogDescriptionMaxLength` 而不是缩短描述。** 否决：这是治标。长度不是缺陷；把实现细节放进选择信号才是。更大的上限还会让目录无界增长，那正是第二个缺口。

**只精简描述，不加门禁。** 否决：下一个 skill 会让同样的情况重现。本仓库既有的做法是把重复出现的条件做成门禁而非一次性清理，`doc-budgets.manifest.json` 就是散文预算的既有形态。

**照搬 Codex 的总体行为：先整体缩短所有描述，再省略条目并告警。** 未采用。它们的初始清单上限是上下文窗口的 2% 或 8000 字符，降级是渐进的且会告知。要做到那个形态需要改 `dsh-tool-skill` 的渲染，并先决定"某条 skill 被隐去时该告诉模型什么"。在过渡期内，预算门禁限制总量，并在源头失败——那里修复成本最低。

**对易误触的 skill 强制 `disable-model-invocation` 策略。** 不需要：仓库已在 `skill-filesystem` 实现该字段，并在 `verify-skill-invocation-metadata` 中与 Codex 的 `policy.allow_implicit_invocation` 交叉核对。当前没有任何仓库 skill 需要它。

## 后果

本应被截断的描述现在在源头失败，并报出 skill 名、长度与上限。缺少触发条件的描述、以及两条 skill 重复声明同一件事，也以同样方式失败。目录不再能无声增长：在预算之外新增第十三个 skill，必须在同一改动里精简一条既有描述——这是有意的摩擦，且在 review 中可见。

450 字符的上限比渲染器允许的更紧，因此某条描述确有更长需求时，它会成为一个明确的策略问题——按 `verify-doc-budgets` 上限的同样要求带理由提高门禁常量——而不是一次意外。两两重叠规则是在去停用词后的词上作的启发式判断；它能标出声明同一件事的描述，但无法判断两个相邻 skill 是否真的不同，因此其阈值是记录在此的判断选择，而不是推导出来的值。

每次运行都会打印已用总量，因此剩余预算无需读源码即可见。这十二条改写也让 `AGENTS.md` 中移除的散文略微变长：持久化类型指针现在自带动词，因此该改动是词数持平而非净减少。
